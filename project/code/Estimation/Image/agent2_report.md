# Agent 2 现有工程算法优化报告

## 输入边界

- 只读取 `C:/Users/23055/Downloads` 下三份指定原始 CSV。
- 融合输入只使用 `I0..I26` 三摄像头原始检测槽位；`I27..I37` 不参与算法。
- 对比基线采用任务给定的 Agent 1 事实，不读取目标目录旧 CSV。
- 强制预处理规则：单帧任一摄像头识别灯数大于标注灯数 `N` 时丢弃；小于或等于 `N` 均保留。

## 现有工程问题定位

- `beacon_fusion.c` 先按几何门限聚类，再将聚类数写入 `beacon_count`。
- 当单帧少检、空帧、跨摄像头匹配失败或同灯被拆分时，输出数量会随观测质量波动。
- 数据集已经有固定真实灯数 `N`，数量目标应由场地配置约束，单帧观测只用于更新位置和置信度。

## Agent 2 核心算法

1. 每帧按原始槽位统计每个摄像头检测数，并执行 `camera_count > N` 丢弃门控。
2. 对保留帧输出数量固定为 `N`，从源头保证数量稳定。
3. 每个摄像头内按 `y` 降序、`radius` 降序、`x` 升序稳定排序，跨摄像头按第 `k` 个观测合成第 `k` 个灯。
4. 若某个灯本帧没有任何观测，则优先沿用上一帧同索引结果并标记 `synthetic=1`；无历史时输出低置信度占位。
5. 距离代理使用 `range_proxy = 900 / radius_px` 的加权平均；半径越大表示越近，仅用于远近定性，不作为厘米级距离。

## 距离远近策略与局限

- 策略：对每个观测计算 `900 / radius_px`，多摄像头同序观测按半径权重融合；同类光斑中半径越大，`range_proxy` 越小，定性表示越近。
- 空观测补位：没有历史时使用 `5000` 作为远距离占位；有历史时保持上一帧距离并降低置信度。
- 局限：未使用完整相机标定、高度和姿态补偿，跨摄像头半径响应不一定一致，因此不能解释为真实厘米距离。

## 工程原则

- KISS：把数量稳定问题拆成预处理门控、期望数量约束、简单融合和缺失补位。
- YAGNI：未引入新依赖、复杂优化器或离线训练。
- DRY：C 实现和 Python 验证脚本共享同一排序、计数、半径反比策略。
- SOLID：新增 `agent2_` 独立接口，不修改原 `beacon_fusion.c/h`，便于人工替换或并行对比。
