# Agent 1 基线测试报告

## 字段解析

- 日志来自 `car_loop.c` 中 `wifi_justfloat(...)` 的 38 个浮点输出。
- `I0..I26`：三路摄像头原始检测，格式为 `3 个摄像头 * 3 个槽位 * (x, y, radius)`；`x/y/radius` 全为 0 表示该槽无灯。
- `I27`：当前工程 `g_beacon_fusion_result.beacon_count`。
- `I28..I37`：当前工程最多 5 个融合灯的 `(bearing_deg, range_proxy)` 成对输出。
- 工程内部 `camera_spi_types.h` 支持每路 5 个槽位，本批遥测只导出了每路前 3 个槽位。

## 预处理规则

严格执行用户指定规则：若某帧任意一个摄像头识别灯数大于数据集标注实际灯数 `N`，该帧丢弃；等于或小于 `N` 的帧保留。

## 问题结论

- 现有算法数量输出不稳定：1 灯数据保留帧仍出现 0 灯和 2 灯；2 灯数据出现 0/1/3 灯；3 灯数据出现 1/2/4/5 灯。
- `range_proxy` 使用固定高度/投影近似，且数据采集时高度和姿态波动明显，绝对距离不可直接视为厘米真值。
- 当前聚类门限依赖跨摄像头投影距离和角度，一旦某路漏检或相机视野重合区排序变化，就会把同一灯拆成多个灯或把多个灯合并。
- 逐帧明细已写入 `agent1_baseline_detail.csv`，包含每帧保留/丢弃状态、当前输出数量和最多 5 个角度/距离。
