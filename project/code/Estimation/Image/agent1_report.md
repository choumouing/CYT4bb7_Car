## 强制预处理

每帧先统计 `I0..I26` 中三路摄像头各自非零目标槽数量；任一摄像头数量大于文件名标注灯数时，整帧标记为 `discarded_overcount`，不送入融合状态机。低于或等于标注灯数的帧保留，并继续由算法自身的 `target_valid` 过滤无效目标。

## 发现的问题

- 当前 `range_proxy` 是基于图像射线和 900mm fallback 标尺的距离代理，不是物理量测距；因此与文件名 cm 坐标换算出的真实距离存在系统性偏差。
- 原始日志只保存每个摄像头前 3 个目标槽，而 `CAMERA_SPI_IMAGE_TARGET_COUNT` 为 5；离线复刻只能将未记录的第 3/4 槽视为无效。
- `100cm_1灯.csv` 文件名未提供横向坐标，本报告按 `(0, 100)cm` 解释；若实际摆放角度不是正前方，该数据集角度误差需重新计算。
- 预处理只按任务要求丢弃“摄像头单帧识别数大于标注灯数”的帧；欠检帧仍进入现有算法，可能触发 `beacon_fusion.c` 的短时保持输出。
