# Agent 3 全新融合算法设计

## 目标

最高优先级是全局灯数量与数据集标注实际灯数量 100% 一致。本交付不计算距离和角度，也不依赖工程目录中已有融合算法或目标目录既有 CSV。

## 输入解释

- 三份原始数据来自 `C:/Users/23055/Downloads`。
- 每行 `I0..I26` 解释为 `3 个摄像头 * 3 个槽位 * (x, y, size)`。
- 单槽位只要 `x/y/size` 任一非零即为有效灯点。
- `I27..I37` 不作为输入，避免复用旧融合结果。

## 预处理

数据集标注灯数记为 `N`。每帧分别统计三个摄像头有效灯点数：

- 任一摄像头 `count > N`：整帧丢弃。
- 所有摄像头 `count <= N`：进入融合。

该规则严格对应任务要求中的“识别灯数大于实际灯数则整帧丢弃”。少检不丢弃，因为最高优先级是输出全局数量，而不是评估单相机召回。

## 融合策略

1. 摄像头内排序：`y` 降序、`size` 降序、`x` 升序、原槽位升序。
2. 排序后的第 `k` 个灯点跨摄像头组成第 `k` 个全局灯簇。
3. 对缺测的第 `k` 个灯簇输出合成占位，`quality=0`。
4. 每个保留帧固定输出 `N` 个全局灯簇。

这样可以把多摄像头对同一灯的重复观测压缩到单个全局簇，同时在少检帧维持数量契约。

## 输出

- `agent3_validate.py`：可运行验证脚本。
- `agent3_beacon_fusion.h` / `agent3_beacon_fusion.c`：独立 C 核心算法。
- `agent3_results.csv`：每个数据集的数量准确率和预处理统计。
- `agent3_fusion_detail.csv`：逐帧、逐簇融合结果。
- `agent3_report.md`：验证报告。

## 工程原则

- KISS：只实现计数门控、排序配对、固定数量输出。
- DRY：验证脚本和 C 核心使用一致的数据解释与排序规则。
- YAGNI：不引入历史滤波、几何标定、距离和角度估计。
- SOLID：C 核心通过单帧纯函数接口交付，可独立测试和替换。
