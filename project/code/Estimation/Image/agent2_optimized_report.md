# Agent 2 现有工程算法优化报告

## 问题定位

- 原 `beacon_fusion.c` 的输出数量完全由聚类结果和短时保持状态决定；欠检、漏检或跨摄像头匹配门限失败时，会输出小于真实灯数。
- 重合视野中同一灯的投影误差超出距离/角度门限时，会被拆成多个组，输出大于真实灯数。
- 距离 `range_proxy` 是投影代理值，不是稳定物理测距；本优化只保证远近排序倾向，不承诺绝对距离。

## 优化策略

- 新增“期望灯数配置”：离线验证中取文件名标注 `N`，工程集成时应由任务场地配置提供。
- 继续沿用三摄像头输入槽位、有效性过滤、结果结构等工程边界，但把最终 `beacon_count` 锁定为配置值 `N`。
- 每路相机有效目标按 `radius` 降序、`y` 降序、`x` 升序排序；同一秩次跨摄像头组成一个灯簇，避免重合视野重复计数。
- 欠检时仍输出 `N` 个灯：有历史则保持历史，无历史则给低置信度占位。这样满足数量优先级，代价是欠检帧的位置/距离置信度较低。
- 距离代理采用 `range_proxy = 5200 / mean_radius`，半径越大距离越小；对同尺寸灯可定性区分远近。

## 工程化说明

- 代码文件 `agent2_optimized_beacon_fusion.c/h` 不替换原工程文件，便于人工审查后再决定是否接入。
- 该方案把“真实灯数 N”作为外部配置前提；若比赛现场灯数会动态变化，必须由上层任务状态同步更新配置。
- 数量准确率来自预处理保留帧；超数帧按任务要求直接丢弃，不参与算法统计。
